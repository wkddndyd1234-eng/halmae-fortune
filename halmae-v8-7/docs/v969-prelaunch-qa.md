# v9.6.9 PG 신청 전 최종 검수

기준 v9.6.8 `707e8112e97d28fcc4c9842fb0009fae828fde0a`. 상품은 39,900원 단건, 개인 사주 장부 26장과 2027년 월별 운세, 승인 시각부터 365일 열람이다.

## PG 신청 전 기술적으로 완료한 검수

- 실제 Chromium 렌더링 기반 격리 환경에서 PC 1280 × 900과 모바일 390 × 844를 확인했다. 합성 음력 윤달·23:35 입력으로 첫 화면 CTA, 무료 풀이, 유료 장부 발췌, 주문 내 양력 환산, 미리보기 열기, 모의 승인과 계약서면, 제26장, 새로고침·같은 브라우저 재접속, 결제 중단 안내를 확인했다. 결제와 권한 응답은 합성 응답을 사용했다.
- 기존 80개 회귀 테스트, 빌드 및 독립 모의 주문·승인·발급·재인가 흐름이 통과했다. 모의 서버에서 권한 없는 브라우저의 열람 링크 재발급이 거절되는 것을 확인했다.
- 검토용 정책 세 페이지와 사업자 정보 파일이 빌드에 포함된다. 정책 원문 버전 및 링크 일치, 운영 관리자 요청 출처·세션·CSRF 제어는 회귀 테스트로 확인했다.
- 빌드 공개 파일을 알려진 라이브 비밀키 패턴과 운영 서명·메일·관리자 비밀 환경변수 이름 기준으로 검사했으며 일치 건은 0건이었다. 빌드 출력은 코드의 공개 파일 허용 목록을 사용한다. 이 검사는 전체 저장소 이력이나 운영 환경에 대한 비밀 탐지 보고서 범위를 포함하지 않는다.
- 운영 키나 설정을 입력하거나 조회하지 않았다. 운영 환경 누락 판정은 Netlify Production의 Functions 변수 이름과 [v9.6.8 설정표](./v968-launch-runbook.md)를 대조할 때 가능하다. 값 자체는 출력·캡처할 필요가 없다. 공개 프리뷰 주소는 이 환경의 외부 확인 경로에서 접속을 확인하지 못했다. 운영 도메인·HTTPS 인증서와 운영 정책 링크는 확인되지 않았다.
- 기능·디자인 수정은 없었다. 화면 캡처는 동일 UI를 사용하는 기준/검수 버전 공통 화면이다.

## 고객 문의 및 장애 응대

| 상황 | 첫 응대 | 운영 처리 |
| --- | --- | --- |
| 일반 문의 | 고객센터 메일로 주문번호와 문제 화면·발생 시각을 요청한다. | 카드번호·보안코드·장부 링크·비밀키는 접수하지 않는다. 확인에 필요한 정보만 기록한다. |
| 결제창 종료·실패 | 다시 결제하기 전에 기존 주문과 승인 여부를 확인한다. | 운영 콘솔과 PG에서 주문을 조회한다. 미승인이 확인되면 동일 브라우저의 재시도를 안내한다. 이미 승인됐으면 재승인을 요청하지 않는다. |
| 승인됐으나 발급 실패 | 결제 승인 사실과 주문번호를 확인하고 진행 상황을 안내한다. | 거래를 재대조한 다음 발급 복구를 시도한다. 지급·장부 상태가 불일치하면 광고·신규 판매 중단 판단을 요청하고 재제공 또는 법정 구제 절차를 적용한다. |
| 장부 링크 분실·만료 | 동일 브라우저의 주문 확인 및 새 열람 링크 받기를 안내한다. | 복구 이메일이 운영 중이고 주문 때 등록한 경우 고객이 복구를 요청할 수 있다. 기기 변경 및 등록 이메일 부재 시 본인 확인 후 가능한 범위를 안내한다. 구매 당시 계약서면 재교부는 관리자 승인 절차로 처리한다. |
| 취소·환불 요청 | 접수 시각, 주문번호, 사유와 고객 연락 경로를 기록한다. | 주문 상태·발급 여부·구매 당시 정책을 확인해 법정 권리와 정책에 따라 판단한다. 담당자 승인 후에만 PG에서 처리하고 정산·열람권을 재대조한다. 부분 취소 시 잔여 열람권은 확정 정책이 필요하다. |

## 사업자가 직접 확인할 일

- 최신 사업자등록증과 주소 변경이 반영된 통신판매업 신고증으로 상호·대표자·등록번호·주소·신고번호를 대조한다. 공개 전화, 고객센터 메일 수신, 개인정보 보호책임자와 담당자를 확정한다.
- [정책 후보안](./v968-policy-candidates.md)의 계약서면 교부 방법, 실제 제공 개시 기준, 결제 전 발췌의 고지·시험 사용 적정성, 가분성, 부분 환불 이후 권한을 검토한다. 개인정보 처리 위탁·국외 이전·로그/캠페인 보존 기간을 운영 계약과 맞춘다. 계약서면 자동 이메일은 운영 구매에 연결되어 있지 않다.
- 실제 Netlify 사이트와 운영 도메인을 대조하고 DNS, HTTPS 인증서, canonical·정책 링크를 확인한다. Production과 프리뷰의 설정·키·저장소 분리를 확인한다. 실제 운영 콘솔의 허용 IP·TOTP·세션 정책, 관리자 접근과 로그 마스킹을 확인한다. 웹훅 URL 키를 쓰면 대시보드·로그·장애 화면에 질의문이 노출되는지 확인한다.
- iOS Safari와 Android Chrome 실기기에서 렌더링·날짜 선택·뒤로가기·복구를 확인한다. 배포 전까지 운영 사이트 속도나 실제 고객 모바일 환경은 확인된 것으로 기록하지 않는다.

## 토스페이먼츠 승인 후 검증할 일

- 승인 가맹점·운영 키·결제수단·정산 정보와 사이트 원점을 대조한다.
- 승인된 결제수단의 실제 결제창·콜백·웹훅을 확인하고, 승인·취소 원장 및 정산 명세와 장부 권한이 일치하는지 검증한다.
- 운영 네트워크에서 거래 오류·승인 응답 유실·발급 복구 및 운영 계약서면 교부를 재검증한다. 사업자 확인과 검수가 완료된 뒤에만 판매 활성화와 광고 시작을 승인한다.

이번 작업에서는 실제 결제·환불·운영 배포·판매 활성화를 수행하지 않았다.
