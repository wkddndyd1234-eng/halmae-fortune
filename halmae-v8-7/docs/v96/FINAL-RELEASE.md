- 36개 가상 출생 조건에서 26개 장의 제목과 12개월 각 여섯 항목, 보고서 명식과 엔진 명식 일치, 확인 가능한 십성, 시간 미상 시주·대운 누락, 절입일 참고값의 과잉 해석을 점검했다. 입춘 경계 전후, 양력 윤일, 음력 평달과 윤달, 자정 및 23시 사례를 포함했다.
- 시간·절기표·명식·십성의 핵심 계산은 수정하지 않았다. 해석 문장만 바꿨다. 재물은 월간 십성을 실제 거래 조건에, 직업은 일지 단서를 기술의 쓰임에, 연애는 일지 관계를 대화에 연결했다. 결혼은 생활비·돌봄·쉼의 예시를 구체화했다. 건강 장은 생활 조건을 돌아보도록 안내하고 질병 결과를 예측하지 않는다. 월별 사업운은 열 가지 십성별 질문과 서로 다른 월별 상황을 함께 제공한다.
- 반복 지표는 공백을 정규화한 문단의 완전 일치만 비교했다. 630쌍의 공유 문단 비율은 두 장부 중 문단 종류가 적은 쪽을 분모로 사용한다. 공통 편집 문장과 비슷한 명식 간 공유 해석이 남는다. 짧은 문장을 제외한 문장 단위 평균 일치 비율은 v9.5보다 소폭 증가했다. 월별 상황과 십성 해설 중 여러 장부가 공유하는 문장은 후속 편집 검토에 남긴다. 금지 표현 검사는 일부 확정형 문구와 미정의 값만 확인하며 의미론적 모순의 자동 판별을 보장하지 않는다.
- 서버는 미확정 통신판매업 신고번호·고객센터 전화·개인정보 보호책임자 중 하나라도 없거나 별도 공개 정보 승인이 없으면 신규 판매와 주문을 닫는다. 승인된 추가 정보만 공개 사업자 페이지에서 서버 응답을 통해 표시한다. 기존 승인의 열람·복구는 신규 판매 잠금과 분리돼 있다.

- 토스 개발자센터 및 상점관리자에서 본인 가맹점 ID, PG 승인 정책, 카드 이벤트 웹훅과 발신 IP, 정산 자료 형식을 검증한다. 예전 URL 질의 비밀은 이전 후 폐기한다.
- Netlify 승인 운영 사이트의 Functions 환경에서 공개 정보·정책·PG·TOTP·접속 허용 IP·키 유예·보존 환경변수를 준비한다. 기존 운영 서명 키는 식별자 재검증용 `LIVE_IDENTITY_SECRET`으로 고정한 뒤 서명 키를 교체한다.
- Resend에서 발신 도메인, 복구와 오류 경보 수신을 확인한다. 실제 설정은 변경하지 않았다. 자세한 키와 승인 기준은 [v9.5 A~D 상태표](../v95/LAUNCH-READINESS.md)를 참고한다.

사업자와 정책, 계약서면 교부가 확정되기 전에는 판매 설정을 승인하지 않는다. 승인된 환경에서 실제 PG 승인·취소·정산, 이메일 실제 수신, 웹훅 발신 주소, 예약 파기·실패 알림, 키 회전 후 기존 고객 열람을 각각 검증한다. 사용 중인 기존 금융기록의 원본 파기와 외부 계약·분쟁 원문 보존은 운영자가 확인한다. Safari, Edge, 정식 Google Chrome은 이 실행 환경에서 별도로 검증하지 못했다. Chromium의 엔진 결과는 별도 브라우저 검증을 대신하지 않는다.

## 로컬 프리뷰

프로젝트 경로에서 아래를 실행한다.

```sh
npm ci
node --test
node qa/audit-v96.mjs /tmp/halmae-v96-audit
node build.mjs
python -m http.server 8492 --bind 127.0.0.1 --directory dist
```

`http://127.0.0.1:8492/`에서 정적 화면과 무료 풀이를 확인한다. 단순 정적 서버에서는 주문·메일·관리자 함수가 비활성 상태다. 유료 동선 검증은 로컬 Netlify Blobs·실제 앱 함수에 모의 토스·Resend 응답을 연결해 실행했다. 오프라인 빌드로는 `netlify build --offline`을 사용한다. 키를 입력하거나 실제 결제를 열지 않는다.
