# v9.7.0 정식 출시 전 안정화

기준 커밋 `e6fa1eb305357c7e4df8d2696d4cd1437d48b8c8`. 상품은 39,900원 단건, 26장과 2027년 월별 운세, 승인 시각부터 365일 열람이다.

## 테스트 차이와 수정

| 조건 | 결과 |
| --- | --- |
| 기준 코드, 실제 Netlify Blobs SDK, 별도 모의 설정 없음 | 77/80. 캠페인 단위 테스트 2건은 Blobs 설정 누락, 주문 통합 테스트 1건은 귀속 경로 불일치 |
| 기준 코드, 실제 SDK, 별도 캠페인 단위 테스트용 모의 설정 추가 | 79/80. 주문 통합 테스트는 귀속 레코드 위치 불일치로 중단 |
| 기준 코드, SDK 자체를 대체한 인메모리 모의 구현 | 80/80. 대체 저장소가 실제 SDK의 `site:` 경로 접두사를 재현하지 않음 |
| v9.7.0, 실제 SDK, 저장소 요청만 격리, 기본 `node --test` | 80/80 |

캠페인 단위 테스트는 실제 SDK에 모의 저장소 요청 함수를 전달한다. 주문 통합 테스트는 SDK가 붙이는 `site:` 접두사를 모의 저장소에서 정규화하고, 삭제 시 실제 모의 레코드를 찾아 제거한다. 캠페인 귀속 한 건과 재시도 중 단일 승인, 구매 계약 재교부를 확인하는 기존 단언을 유지했다. 변경은 테스트 코드에 국한된다.

## 고객 및 운영 검증

- Edge 1280 × 900과 모바일 에뮬레이션 390 × 844에서 첫 화면과 무료 풀이 CTA, 음력 윤달 출생 입력부터 개인화 미리보기, 39,900원 주문, 모의 승인, 계약서면, 26장과 2027년 1~12월, 장부 새로고침과 같은 브라우저 재접속, 결제 중단 안내를 점검했다.
- 첫 화면에서 할매 캐릭터와 무료 풀이 CTA가 함께 보이고, 주문에서 출생 입력이 승계되고 실제 장부 일부가 펼쳐지는 것을 확인했다. 39,900원 주문 버튼과 단건 상품 정보가 보인다. 전환율과 실제 구매 의향은 측정하지 않았다.
- 회귀 테스트에서 365일 만료, 주문 중복 승인 방지 및 재조회, 취소·환불 상태 반영, 관리자 세션·CSRF, 미승인·비인가 접근 차단, 계약 원문 재교부, 캠페인 귀속·순매출 집계를 확인했다. 판매 스위치를 끄면 신규 주문은 막히고 기존 승인 구매자는 계속 열람 가능하다. 운영 환경 적용은 확인 대상이다.

## 출시 판단

정식 출시 보류. [정책 후보안](./v968-policy-candidates.md)과 [출시 당일 매뉴얼](./v968-launch-runbook.md)을 사용해 다음을 확인한다.

- 대표자 확인: 최신 사업자등록증·통신판매업 신고증 대조, 고객센터 전화·이메일 담당 및 개인정보 보호책임자 확정, 정식 이용약관·개인정보처리방침·환불 및 청약철회 고지 승인, 부분 취소 후 열람권과 계약서면 교부 방식 결정. 자동 계약서면 이메일은 운영 구매에 연결되어 있지 않다.
- 무상으로 진행 가능한 검증: 운영 도메인·HTTPS·정책 링크 및 Netlify 설정 이름과 범위 대조, 운영 관리자 인증과 복구 메일 설정 확인, 실기기 iOS/Android 구매 동선 점검, 문의 접수 및 복구 절차 리허설. 운영에서 캠페인 수집 설정과 개인정보 보유·파기 범위를 검토한다.
- PG 승인 이후 확인: 운영 가맹점·키, 실제 결제창 및 콜백·웹훅, 정산과 취소 반영, 실구매자의 계약 교부와 장부 열람. 승인 및 검증 후에만 판매 개시를 결정한다.

실제 결제·환불, PG 신청, 광고 제작, 운영 배포와 main 병합을 수행하지 않았다.
