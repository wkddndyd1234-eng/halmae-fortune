# v9.5 출시 준비 상태표 · 2026-11-24 KST

## A. 코드로 구현하고 검증할 수 있는 사항

| 항목 | 현재 상태 |
| --- | --- |
| 운영 관리자 | 서버 세션에 scrypt 비밀번호, RFC 6238 TOTP, 일회 사용 처리, Netlify 신뢰 컨텍스트 IP 허용 목록, IP별 로그인 한도 적용. 운영용 Bearer 경로에도 IP 제한 적용. 프리뷰 인증 설정 분리 |
| 웹훅 | URL 비밀 없는 카드 알림 경로에 토스 IP 확인·크기 제한·발신지 및 주문별 제한 적용. 확정 상태는 가맹점 키를 사용한 토스 조회 결과로만 저장. 불일치 또는 수신 처리 실패는 재시도 응답 및 점검 기록. 기존 query 모드는 이전용이며 운영에서는 폐기 대상 |
| 키 교체 | 서명 키 유예와 별도 `LIVE_IDENTITY_SECRET`을 사용해 기존 서명·브라우저·등록 이메일 대조를 분리할 수 있음. 운영 키나 사용자 자격은 변경하지 않음 |
| 구매 고지 | 승인 정책 URL 3종과 버전을 불러오고, 구매 조건 확인과 즉시 제공 요청을 서버에서 검증. 주문 및 금융 기록에 동의 당시 버전·시각 기록. 승인 없이 새 판매는 닫힘 |
| 금융·정산 | 이전 저장소 금융기록을 허용 필드만 검증 복사. 대상 확인과 반복 실행 지원. 승인일 범위의 전체 입력에 대해서는 양방향 누락·중복·금액·거래 키 대조. CSV에 고객정보 미포함 |
| 보존 | 6개월 광고, 3년 불만·분쟁, 5년 계약·철회 및 지급·공급 기준의 참조 인덱스. 승인된 자동 파기는 금융 스냅샷과 인덱스에 적용. 보류가 우선하며 원문 외부 보관·법정 기산일은 운영 확인 필요. 기존 365일 주문 삭제·실패 경보·재실행 유지 |

코드 기준은 일반 카드 결제 상태 이벤트다. 토스 문서에 서명 헤더가 소개되어 있지만 가맹점 카드 계약에서 서명 키가 제공되는지 출시 전에 확인한다. 이 구현은 카드 알림의 본문·헤더를 재무 인증 근거로 사용하지 않는다. [토스 웹훅 연결](https://docs.tosspayments.com/guides/v2/webhook) · [웹훅 이벤트](https://docs.tosspayments.com/reference/using-api/webhook-events) · [토스 방화벽](https://docs.tosspayments.com/reference/using-api/security) · [Netlify Functions IP](https://docs.netlify.com/build/functions/api/)

## B. 운영자가 확인해 입력할 사항

- 주식회사 밸류시커의 대표자, 사업자등록번호, 주소, 고객 전화번호, 통신판매업 신고 및 개인정보 책임자·접수 창구. 사업자등록증과 신고 확인서로 대조하고 실제 고객 문의가 수신되는지 확인한다.
- 개인정보 계약 담당자는 토스·Netlify·Resend에서 계약 주체, 수탁·제공 관계, 이전 국가와 리전, 처리 목적·기간·거부 절차를 확인한다.
- 책임자는 계약서면 교부 방식, 즉시 제공·샘플과 철회 고지, 부분 취소 후 잔여 권한, 법정 기록별 기산일·분쟁 보류·백업 파기 절차를 확정한다. 현재 코드는 부분 취소 시 보수적으로 권한을 차단한다. [전자상거래법 제17조](https://www.law.go.kr/법령/전자상거래법/제17조) · [시행령 제6조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1018638379)
- 게시용 정책 파일은 [약관](./publish/terms.md), [개인정보처리방침](./publish/privacy.md), [환불](./publish/refunds.md)이다. 검토 표시와 자리표시자를 승인 문안으로 교체한 후 별도 게시한다. 빌드 공개 파일에서 제외돼 있다.

## C. 외부 서비스 설정과 승인

| 접근할 서비스 | 필요한 값과 설정 | 승인 기준 |
| --- | --- | --- |
| Netlify 운영 사이트 → Functions 환경변수 | `OPS_LIVE_ALLOWED_IPS`에 함수가 관찰하는 승인된 고정 IP 목록, `OPS_LIVE_TOTP_SECRET_HEX`에 인증 앱과 공유하는 20~64바이트 키의 hex, 기존 관리자 해시와 `OPS_ADMIN_ENABLED`. 기존 서버용 Bearer 경로도 같은 IP 제한 | 운영자 VPN 출구를 승인하고 비허용 IP, 오류 코드 및 재사용 코드가 거부돼야 함 |
| 토스 개발자센터·상점관리자 | 카드 이벤트 URL을 query 없이 등록. 공식 송신 주소를 확인해 `PAYMENT_WEBHOOK_PUBLIC=true`, `PAYMENT_WEBHOOK_ALLOWED_IPS` 설정. 이전 query 비밀 삭제·교체 및 로그 마스킹 | 확인된 송신지에서 수신, 조회 가맹점 일치, 중복·지연·실패 시 재대조 및 취소 권한 검증 |
| Netlify 구매 정책 | 최종 승인 URL을 `LIVE_TERMS_URL`, `LIVE_PRIVACY_URL`, `LIVE_REFUND_URL`에 지정하고 `LIVE_POLICY_VERSION`을 지정. 승인 전 `LIVE_POLICY_APPROVED`, `PAYMENT_LIVE_SALES_ENABLED`, `PAYMENT_REFUNDS_APPROVED`는 비활성 상태 유지 | 법률 검토·운영자 승인, 동의 버전 검증, 취소 절차 확인 후 승인된 별도 배포 |
| Resend 발신 도메인 | 발신 주소·키와 경보 주소 DNS 검증. 실제 수신·스팸 분류·링크 교환 확인 | 고객 단말이나 외부 이메일에서만 실제 수신 검증 |
| Netlify 보존 설정 | 원본과 대상 비교 후 `LIVE_RETENTION_ENABLED` 및 별도 `LIVE_FINANCE_PURGE_APPROVED` 승인. 금융 이관 테스트와 보류 백업 후 실행 | 이관 불일치 0, 집계 및 거래 샘플 일치, 법정 보존 중·분쟁 관련 자료 제외 확인 |

이전 변수와 운영 설정은 [v9.3 결제 안내](../../PRODUCTION-PAYMENTS.md), [v9.4 운영 안내](../v94/OPERATIONS.md)를 함께 본다. 기존 운영 키를 교체하기 전 기존 값을 `LIVE_IDENTITY_SECRET`으로 고정해 브라우저와 복구 주소 대조값을 보존한다. 기존 서명 키와 유예 종료 시각을 별도 설정한 뒤, 유예 종료 후 이전 키를 제거한다.

## D. 승인된 실제 운영에서 검증할 사항

- 실제 PG 승인·부분/전액 취소·정산, 토스 발신 IP가 Netlify 컨텍스트에 보이는 방식, Resend 실수신과 Netlify 예약 삭제·경보. 실제 운영 자격으로 실행하거나 배포한 이력은 이번 작업에 없다.
- 금융 이관은 복사·대조만 수행한다. 실제 기존 원본의 승인된 파기, 광고·계약·분쟁 원문용 제한 저장소와 외부 원문 파기, 백업·감사 기록 보존은 운영자가 확인한다. 인덱스 파기는 외부 원문까지 삭제하지 않는다.
- 승인 날짜 범위 전체의 정산 자료를 PG에서 확보해 비교한다. 비교 자료를 자동 수집하지 않는다. 전체 비교는 대시보드의 표시 상한과 별도로 저장소를 끝까지 읽는다. 500건 입력 한도를 넘으면 승인일 범위를 나눠 완전한 파일로 비교한다. 운영 데이터 규모에서 실행 시간을 확인한다.
- 즉시 제공 이후 청약철회, 부분 취소 후 남은 권한과 계약서면 전달 방식은 운영·법률 검토가 끝나기 전까지 판매 차단 요소다. 기존 고객 재열람, 서명 키 교체, 실패한 메일·발급의 재처리는 실제 운영 자격에서 승인받은 점검으로 확인한다.
