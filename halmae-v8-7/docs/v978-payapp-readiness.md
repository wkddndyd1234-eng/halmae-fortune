## 가맹점과 결제 연동

사용자 제공 상태는 11월 27일 법인 판매자 가입, 판매자 ID valueseeker123, 11월 30일 전자계약서 수신 예정이다. 약 3일은 사용자 안내 기준이며 가입비 면제, 비실물 거래 수수료, 보증보험, 심사와 정산은 계약 및 가맹점 확인 사항이다. 사업자 공개 정보에는 사용자 제공 사업자등록증명 기준 상호·대표·번호·새 상세 주소·이메일을 반영했다. 변경된 통신판매업 신고증, 신고기관, 공개 전화번호, 개인정보 보호책임자는 확인 후 반영한다.

`netlify/lib/payapp.mjs`는 기존 토스 구현과 분리된 서버 라이브러리다. 전송 함수가 명시적으로 주입되어야 하며 배포된 서버 진입점에서 호출되지 않는다. 공식 REST 결제 요청의 고정 가격, 휴대전화, SMS 비발송, 통지 및 복귀 주소, 결제번호와 HTTPS 주소 확인을 구현했다. 동일 주문의 재사용, 통지 계정·키·해시·주문·거래·가격 확인, 전액 취소 요청, 부분 취소 통지 구분, 승인시간 +365일을 모의 테스트했다. 공급사 요청이 처리됐는지 모르는 시간 초과 시 같은 요청을 자동 재전송하지 않고 관리 대조로 넘긴다. 환불 요청 접수와 취소 완료는 구분한다.

운영 전 해야 할 일:

1. 가맹점에 카드 결제·정산 승인, 디지털 사주 장부 취급 가능 여부, 수수료, 가입비 면제, 보험, 결제 시험 방법을 서면으로 확인한다. REST 요청은 구매자 휴대전화가 필수이므로 보유·제공 고지를 확정한다.
2. 인증값은 운영 함수 환경에서만 관리한다. 예정 이름은 `PAYAPP_USER_ID`, `PAYAPP_LINK_KEY`, `PAYAPP_LINK_VALUE`, `PAYAPP_REQUEST_KEY`다. 이 브랜치는 이 환경변수로 활성화할 수 없다.
3. 승인된 호스트에서 주문/서버 통지/재열람의 실제 경로를 연결한다. 서버 통지 본문은 공식 응답과 대조하고, 저장 성공 및 중복 통지에는 SUCCESS를 반환한다. 문서의 해시 입력은 판매자·시각·키로 구성된다. 독립적인 거래 상태 조회 API는 공개 명세에서 확인되지 않았으므로 가맹점에 거래 상태 대조 수단을 문의한다. 브라우저 복귀값만으로 발급하지 않는다.
4. 계약 원본 보존, 장부 권한·복구, 관리자 취소·감사, 정산 기록을 결제사별로 연결한다. 결제사 변경 시 기존 고객은 원 결제사로 재검증하고 정산한다. 페이앱 관리자의 취소 및 통지 누락까지 확인한다.
5. 실결제 없이 가능한 공급사 승인 환경에서 PC·모바일을 먼저 검수한다. Android/iOS 카카오톡과 인스타그램 각각에서 결제창 열기, 실패·뒤로가기·재시도, 복귀, 새 브라우저 및 이메일 복구를 확인한다. 운영 실거래 검증은 별도 승인 범위다.

## 공개 정책 최종 검토안

- **이용약관** · 39,900원 단건으로 개인 장부 26장과 2027년 월별 운세를 구입한다. 결제 승인 시각부터 365일 웹에서 열람한다. 제공 개시는 결제 승인 문구와 구분하고, 구매자가 실제로 웹 장부에 접근할 수 있게 제공한 시각과 오류 기록으로 확인하는 안을 검토한다. 제공 지연이나 하자 시 고객센터에서 재제공·환급을 처리한다.
- **개인정보처리방침** · 현행 출생 정보·계약·결제 식별·복구 처리에 더해 페이앱 결제 요청에 필요한 휴대전화 처리 목적, 페이앱 전달 및 보유 기간을 확정한다. 주문의 계약교부 이메일과 선택 복구 이메일, 마케팅 동의를 구분하고 계약교부용 주소의 사용 기간과 저장을 최소화한다. 위탁/제공/국외 이전의 실제 관계와 고지, 삭제·권리 행사·보호책임자 및 시행일을 확인한다.
- **취소 및 환불** · 결제 전 구매 조건, 제한 가능성, 본문 일부 시험 사용 수단을 읽을 수 있게 한다. 청약철회는 법정 기간 및 기산점에 따른다. 디지털콘텐츠 제공 개시와 명확한 제한 표시 및 시험 사용 등 법정 요건 충족 범위에서만 제한 가능하다. 미제공, 하자, 계약 불일치, 법정 예외 및 가분 부분의 권리를 남긴다. 결제 전 동의가 법정 권리 포기로 해석되는 문구는 피한다.
- **부분 환급** · 중복 결제·미제공·정당한 전체 취소 등은 전체 취소를 기본 검토한다. 일부 환급이 필요한 경우 환급 근거와 남은 열람 범위를 기록한다. 현재 기술 상태는 부분 취소 통지를 받으면 전체 접근이 보류된다. 법적 근거 없이 전체 열람을 영구 차단하지 않도록, 부분 환급 시 기존 365일 권한 유지 또는 합의·법정 기준에 따른 범위별 권한 처리를 확정하기 전 자동 처리를 운영에 연결하지 않는다.
- **구매 전 확인** · 사업자·가격·상품·기간·공급·환불 조건과 시험 사용을 결제 전에 보여 준다. 약관, 즉시 제공 요청, 정보처리 고지 및 별도 선택 동의를 구분한다. 구매 당시 정책 원문·버전과 공급 상태를 보관한다.

## 계약서면과 이메일

기존 결과 화면 다운로드와 관리자 본인 확인 후 재교부를 활용한다. 신규 `contract-delivery.mjs`는 주문·상품·가격·승인·만료·판매자·구매 당시 정책 원문·복구 안내를 전송하는 모듈이다. 합성 수신자로 503 후 동일 멱등 키 재시도와 영구 오류 시 고객센터 이관 판정을 검증했다. 운영 자동 전송 호출부와 발송 보류 기록을 아직 연결하지 않았다. 이메일 발송 실패 시 동일 보존본을 고객센터에서 재교부하며, 메일 API 접수와 실제 받은편지함 도착을 구분한다. 실제 공급 시점까지 계약내용이 전달되는 운영 경로를 확인한다.

초기에는 기존 복구 코드와 같은 Resend 권장. 무료 하루 100건·월 3,000건, Pro 50,000건에 월 20달러다. Brevo 무료 하루 300건, Starter 월 9달러부터이며 전송 어댑터 추가 작업이 필요하다. 계약서면·복구·재발송 전체를 합산한다. 운영 도메인에서 DNS 발신 인증 후 서버 전용 키를 사용하고 Naver/Gmail을 포함해 수신, 스팸함, 반송, 재교부를 확인한다. 기존 복구 변수는 `LIVE_RECOVERY_RESEND_API_KEY`, `LIVE_RECOVERY_FROM_EMAIL`이다. 요금과 운영 조건은 서비스 선택 시 재확인한다.
