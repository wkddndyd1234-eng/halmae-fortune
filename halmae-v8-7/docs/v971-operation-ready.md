# v9.7.1 운영 준비

기준 커밋 `074d0cf619a87994c74e1c9e5a02fd464174d520`.

홈페이지 최하단과 사업자 정보에 대표자가 확인한 상호, 대표자, 등록번호, 주소, 이메일을 표시한다. 신규 계약서면의 주소에도 동일한 값을 사용한다. 기존 보관 계약에는 구매 당시 정보를 유지한다. 문의는 이메일을 우선한다. 공개 전화, 신고번호, 개인정보 보호책임자는 운영 환경에서 확인된 값을 입력한 뒤 기존 사업자 고지 검증을 거친다. 홈페이지의 전화 표시는 텍스트이며 별도 전화 상담 버튼을 추가하지 않는다.

## 공개 전 정책 결정

- `terms.html`, `privacy.html`, `refund.html`은 공개용 초안이다. 시행일, 위탁·국외 이전, 접속 및 캠페인 보유·파기, 권리구제 창구, 보호책임자를 운영 사실에 맞게 확정한다. 최종 페이지와 동일한 정책 원문을 구매 버전별로 보관한다.
- 결제 전 실제 유료 장부 일부를 제공한다. 정상 제공 이후 청약철회 제한을 적용할 때는 제공 개시, 사전 표시, 시험 사용 제공과 가분성을 검토한다. 발급 실패·미제공·중복 결제·시스템 오류·계약 불일치는 접수해 주문과 실제 제공 상태를 확인한다.
- 부분 환불은 발급이 개시되지 않은 가분적 부분의 법정 권리를 검토한다. 현재 확인된 부분 취소도 장부 전체 열람을 중단한다. 최소안은 우선 자동 부분 취소를 도입하지 않고, 적용 범위·잔여 열람권을 승인된 정책으로 정한 뒤 담당자가 건별로 처리하는 것이다. 잔여 열람을 보장해야 하는 경우 그 권한을 실제로 유지할 수 있는 절차나 코드가 필요하다.
- 계약서면 최소안은 공급 시점까지 고객이 저장 가능한 웹 서면을 제공하고, 주문번호 기준으로 구매 당시 정책 원문과 교부 이력을 보존하며, 본인 확인을 거쳐 재교부하는 방식이다. 결과 화면 표시·저장과 원문 재교부 구현은 존재한다. 웹 제공 방식 및 제공 시점의 적정성을 확인한다. 별도 이메일 교부가 필요하면 복구 메일과 분리해 연동한다.

## Netlify 운영 계정 읽기 전용 확인표

현재 운영 계정에 접근할 수 없었다. 아래는 대조 위치이며 설정 누락 여부, 운영 TLS, 정책 링크 실제 주소 및 관리자 접근 결과는 미확인이다. 기존 테스트 프리뷰 주소로 운영 사이트를 판정하지 않는다.

| 위치 | 확인할 항목 |
| --- | --- |
| 프로젝트의 Domain management | 실제 서비스 기본 도메인, DNS, HTTPS 인증서 발급·갱신, 리디렉션. HTTPS에서 홈과 세 정책 페이지 및 사업자 정보를 열어 확인 |
| Environment variables | [설정표](./v968-launch-runbook.md) 기준으로 이름·Production 범위·Functions 적용 여부를 대조. `SITE_PUBLIC_ORIGIN`은 Builds 확인. 승인 전 판매 플래그 유지. 비밀값은 복사·캡처하지 않음 |
| Deploys 및 프로젝트 목록 | 운영 사이트 ID·URL과 프리뷰 분리, 테스트 PG 키·저장소와 운영 PG 키·저장소 분리 |
| Functions 및 관리자 화면 | 운영 관리자 허용 IP·TOTP·세션 확인. 문의 접수, 기존 주문 재조회, 열람 복구·계약 재교부를 합성 데이터로 점검 |
| Resend와 Functions | 발신 도메인 인증 및 복구용 발신 주소, 테스트 수신, 운영 장애 알림 설정 확인. 계약서면 자동 발송은 별도 결정 |
| 관리자와 Blobs | UTM 유입 및 캠페인 CSV, 승인·환불 중복 제거와 광고비 입력 확인. 개인정보와 캠페인 보유기간 및 파기 담당자, 금융 기록 및 분쟁 보류·삭제 정책을 승인 전 확정 |
