# v9.6.5 운영 검수와 판매 승인 전 남은 사항

기준 브랜치 `work/v964-commerce-readiness`, 기준 커밋 `7651697b5c09d781ce622e56beb8e820439cfd32`. 검증은 모의 공급자와 모의 저장소에서 수행했다. 실제 판매 설정 변경, 배포, 결제·취소와 외부 메일 발송은 없었다.

## 사업자 표시와 증빙

사업자 페이지에 이전부터 공개된 상호, 장철근 대표자 표기, 등록번호, 서초구 주소, 문의 이메일과 운영시간이 있다. 이 값의 출처는 저장소이며 사업자등록증이나 신고증을 열람한 결과가 아니다. 미승인 화면에는 증빙 대조 전임을 표시한다. 공개 전화, 통신판매업 신고번호, 개인정보 보호책임자는 운영별 승인 플래그와 값의 형식 검사를 통과해야 표시된다. 형식 검사와 운영 승인 플래그가 실제 서류를 검증하지는 않는다.

운영자는 사업자등록증·신고증과 공개 주소·대표자·등록번호를 대조하고, 신고기관, 전화, 이메일 수신과 담당자, 개인정보 권리행사 창구를 확인한다. 확인 후 승인된 값과 정책을 실제 운영 설정에 적용하고, 홈/주문/사업자 화면의 최종 표시를 검수한다. 이번 작업에서 환경값을 설정하거나 증빙을 승인하지 않았다.

## 계약 원문과 재교부

- 승인 문안이 준비되면 운영 설정의 `LIVE_POLICY_ARCHIVE_JSON`에 `version`과 `terms`, `privacy`, `refund`의 `{url,text}`를 제공한다. 버전은 `LIVE_POLICY_VERSION`과, 각 URL은 기존 승인 URL과 일치해야 한다. 각 본문은 최대 30,000 UTF-8 바이트다. 승인된 공개 원문과 저장 본문의 대조는 운영자가 한다.
- 유효한 원문 설정이 없으면 신규 판매 가능 상태를 반환하지 않는다. 주문은 결제 화면에 안내한 버전과 해시가 현재 값과 같은지 검증하고, 정책 원문을 별도 금융 저장소에 버전별로 원자적으로 등록한다. 같은 버전의 본문이나 URL을 교체하려는 주문은 거절된다. 새 원문은 새 버전과 버전별 공개 주소를 사용한다.
- 승인 시 판매자, 상품, 가격, 승인 시각, 만료와 정책 해시를 담은 사본을 주문 저장소와 분리해 보존한다. 고객의 결제 결과에서 구매 당시 세 정책 원문을 텍스트 사본에 포함해 저장할 수 있다. 공개 정책 URL이 수정되더라도 이 파일에는 보관된 원문이 들어간다. 계약 사본은 기존 승인된 보존기간 만료 작업과 법정 보존 보류를 따른다. 정책 원문의 장기 보존과 폐기 기준은 운영자가 정한다.
- 브라우저 정보를 잃은 고객은 고객센터에 주문번호와 문의 내용을 전달한다. 운영자는 토스 상점관리자의 결제번호·일시·금액과 고객이 제출한 영수증 등으로 본인 및 전달 경로를 확인한다. 주문번호나 금액만으로 본인을 확정하지 않는다. 전체 카드번호, CVC, 열람 링크, 신분증 원본은 이 기능에 입력하지 않는다. 확인 방식과 접수 기록의 보유기간을 운영·개인정보 검토에서 확정한다.
- 본인 확인을 끝낸 담당자가 IP 제한·다중 인증이 적용된 운영 콘솔에서 두 번 입력한 주문번호, 개인정보 없는 `CASE-...` 접수번호, 확인 표시로 사본을 생성한다. 감사 기록에는 접수번호와 주문번호를 남긴다. 확인 표시는 담당자의 확인 사실을 기록하며 고객을 자동 인증하지 않는다. 사본 생성 기록과 실제 전달 완료 기록은 별도로 관리한다.
- 기존 v9.6.4 이전·이후의 구매 기록 중 이 보존 구조 적용 전에 승인된 건은 운영자가 당시 원문과 거래기록을 확인해 수동으로 재교부한다. 지금의 정책으로 과거 계약을 소급 생성하지 않는다. 이때 사본 재교부가 장부 열람권을 복구하거나 취소를 반전시키지는 않는다.

`contract-mail-preview.mjs`는 합성 계약만 Resend 고정 테스트 수신자에 보내는 검수용 모듈이다. 테스트는 네트워크를 모의했으며, 실제 발신 도메인이나 수신·반송·서면 교부를 검증하지 않았다. 실 운영 발송은 수신자 확인, 이메일 수집 근거 및 보유기간, 별도 전송 동의 필요 여부, 실패 시 대체 교부와 교부 시점 요건을 확정한 뒤 검토한다. 현행 복구 이메일은 계약서면 발송에 사용되지 않는다. [전자상거래법 제13조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1031806027) · [Resend 테스트 수신자](https://resend.com/changelog/sending-test-emails)

## 39,900원 단건 상품의 환불과 잔여 열람권

현재 운영 경로는 결제사 확인을 거친 `CANCELED`와 `PARTIAL_CANCELED` 모두에서 장부 접근을 차단한다. 26장 단건의 개별 장별 구매 권리나 안분 금액은 현재 구현에 없다. 정상 승인된 주문은 기존 365일 기한을 적용한다. 취소와 별개로 구매 계약 사본을 조회할 수 있다.

## 검증

기존 회귀 테스트 74개와 추가 3개를 모의 환경에서 실행했다. 정적 빌드도 검증했다. 새 검증은 정책 원문의 해시·동일 버전 변경 거절, 만료·보류 파기, 새 거래의 부분 취소, 합성 문서 이메일 경로를 다룬다. 기존 운영 결제 회귀 테스트에 전체 취소 후 주문 저장소 기록을 지운 상태의 재교부, 운영 확인 표시 및 CSRF 거절, 원래 정책 원문과 민감정보 미포함 검증을 추가했다. 실제 공급자, 운영 또는 모바일 브라우저 재검증은 이번 작업 범위에 포함되지 않았다.
