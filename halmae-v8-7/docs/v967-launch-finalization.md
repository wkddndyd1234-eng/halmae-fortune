# v9.6.7 출시 검수와 캠페인 집계

## 캠페인 사용법

광고 링크의 예시는 `/?utm_source=naver&utm_medium=cpc&utm_campaign=newyear_2027_a`다. 세 값 모두 영문 소문자로 시작하는 1~48자의 영문 소문자, 숫자, 밑줄, 하이픈으로 구성한다. 고객 정보, 연락처, 검색어, 광고 클릭 식별자는 태그에 넣지 않는다. 실행 차수마다 캠페인 이름을 바꾼다.

같은 탭에서 처음 확인한 유효한 태그를 유지한다. 방문과 무료 시작·완료, 구매 클릭, 주문 진입은 방문 무작위 ID의 해시와 단계로 중복을 제어한다. 태그가 없는 유입은 행동 집계 범위에서 제외되며 결제는 미귀속 행에 포함된다. 브라우저 저장 거부, 다른 탭·기기, 전송 실패로 행동 건수가 실제보다 적을 수 있다. 자동화된 트래픽은 행동 건수에 영향을 줄 수 있다.

결제 성과는 기존 금융 원장의 확인된 승인 기록을 주문별로 한 번 읽는다. 모의 승인과 미결제는 매출에서 제외한다. 동일 주문에 승인과 취소 기록이 함께 있으면 확인된 최저 잔액을 사용한다. 총 승인액에서 잔액을 빼 환불액을 계산한다. 환불은 환불일 광고가 아닌 원래 구매 캠페인에 반영한다. 과거 주문을 소급 귀속하지 않는다.

운영 관리자 메뉴에서 캠페인별 누적 광고비를 원 단위로 저장하고 CSV를 내려받을 수 있다. 추정 기여액은 환불 반영 매출에서 입력한 광고비를 뺀 값이며, 광고비 미입력 시 빈칸이다. PG 수수료, 세금, 기타 비용은 사업자가 별도로 반영한다. CSV는 한도 초과 시 내려받기를 차단한다. 동작 한도는 행동 기록 10만 개, 금융 원장 저장소별 1만 개, 광고비 항목 1천 개이며 운영에서 응답 시간과 예상 시즌 처리량을 확인한다.

## 운영 확인

- 기존 운영 승인 조건을 충족하는 환경에서만 `CAMPAIGN_MEASUREMENT_ENABLED=true`로 계측과 관리자 CSV를 활성화한다. 이번 작업은 운영 플래그를 변경하지 않았다.
- 광고 분석은 사이트의 별도 Blobs 저장소를 사용한다. 외부 광고 도구 전송은 없으며, 출생 정보, 이메일, 장부 원문, 토큰은 이 저장소 또는 CSV에 쓰지 않는다. 주문과 캠페인의 연결에는 주문번호 해시를 사용한다. 시즌 종료 후 행동·캠페인 기록 보유 및 삭제 시점과 Netlify 접속 로그 보유기간을 운영자가 확정한다.
- 사업자등록증과 통신판매업 신고증 대조, 약관·환불·개인정보처리방침 확정, 토스 운영 승인과 Netlify 운영 설정은 실제 자료를 받아 확인한다.
- 웹에서 계약서면과 원문을 보존·재교부하는 기존 기능을 유지한다. 정식 교부 채널과 운영 이메일 설정·수신은 미검증이다.
- Edge PC 및 400 × 877 모바일 에뮬레이션에서 합성 출생 정보, 주문 정보 승계, 모의 승인, 계약서면, 26장 보고서와 복구 경로를 확인했다. 실기기와 실제 PG·메일은 미검증이다.
- 부분 취소 잔여 열람권 동작은 기존 정책 그대로 두었다.
