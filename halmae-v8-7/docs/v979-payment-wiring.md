# v9.7.9 페이앱 결제·계약서면 검수

기준 e8005bdef69b4d156ae9ec2aa55e4d5f7e920519 · 12월 4일은 조건부 목표

## 검증된 서버 흐름

1. 주문 서버가 출생 입력, 동의 및 보관 정책 버전을 확인한 뒤 39,900원 요청을 생성한다. 구매자 전화번호는 결제창 생성을 위해 페이앱에만 전달하고 주문·계약 저장소에 남기지 않는다.
2. 페이앱 브라우저 복귀는 조회만 한다. 서버 통지에서 공식 키·해시와 저장한 주문번호, 난수 참조값, 결제 요청 번호, 가격 및 상태를 대조한 경우에만 승인한다. 중복 통지는 같은 승인으로 처리한다. 거래 요청 결과가 유실되면 중복 생성하지 않고 관리자 대조를 요청한다.
3. 승인 시각을 기준으로 365일 권한과 구매 당시 계약 원문을 보존한다. 같은 브라우저의 보안 쿠키 또는 선택 복구 이메일로 장부 열람을 확인한다. 취소 후에도 계약 원문은 보호된 재교부 절차를 통해 확인할 수 있다.
4. 계약 이메일은 전용 서버 키로 암호화하여 대기 상태에 저장한다. 메일 전송에는 주문별 멱등 키를 사용하고 일시 장애 시 재시도한다. API가 접수하면 `api-accepted`, 자동 교부 실패 또는 복구할 수 없는 모호한 응답은 `customer-support`로 기록한다. 양쪽 모두 받은편지함 도착은 `unverified`이며 운영자 확인이 필요하다. 발송 처리 종료 후 주소 암호문을 삭제한다. 아직 보내지 못한 주소는 승인된 고객정보 삭제 절차에서 제거한다. 관리자 이메일 재교부는 구매 확인 후 기존 보존본을 내려받는 절차로 처리한다.
5. 관리자는 기존 접근 통제와 환불 승인 조건 아래 전액 취소를 요청한다. 결과는 서버 통지로 확정한다. 부분 취소 통지는 자동 열람을 임시 보류하며 영구 권리 소멸이나 일률적인 환불 규칙으로 채택하지 않는다. 잔여 권리 기준과 복원 절차를 출시 전에 승인해야 한다.

## 정책 운영 검토안

- 약관은 39,900원 단건·개인 장부 26장·2027 월별 운세·승인 시각부터 365일을 명시한다. 결제 승인과 실제 제공 개시를 구분하고, 공급까지 구매 당시 계약서면을 제공할 수 있는지를 운영에서 검증한다. 동시에 계정 미사용 고객도 결제 결과 다운로드를 이용하도록 한다.
- 개인정보 고지에 페이앱 제공 전화번호의 목적과 실제 처리 근거·페이앱 측 보유기간을 명시한다. 계약교부 주소와 선택 복구 주소의 용도를 분리한다. 복구 주소는 대조용 값만 보관한다. 마케팅은 이 흐름에서 동의받거나 발송하지 않는다. 발송 위탁 및 국외 이전 여부, 미전송 암호문의 최대 보유 기간, 보안키 교체, 삭제 주기와 권리행사 정보를 운영 전에 확정한다.
- 환불은 약정 및 법정 권리를 따른다. 디지털콘텐츠의 제한 표시는 실제 제공 개시와 시험 사용 수단 요건을 함께 검토한다. 미제공, 하자, 계약과 다르게 제공된 경우 및 법정 예외를 유지한다. 부분 환급 후 잔여 권리와 가분성은 별도 정책 결정을 거친다.
- 사업자 고지의 신고기관 설정을 추가했다. 신고번호·신고기관·전화·개인정보 보호책임자 및 정책 버전은 증빙과 검토 완료 후 입력한다.

## 판매 잠금 및 남은 확인

- 운영 결제사 선택은 `PAYMENT_PROVIDER=payapp`로 구분한다. 검증된 운영 호스트에서 가맹점 승인, 정책과 사업자 고지, 서버 전용 페이앱 키와 메일 설정, 전용 `PAYAPP_CONTRACT_EMAIL_KEY`, 판매 승인 플래그가 갖춰지기 전에는 신규 페이앱 판매가 열리지 않는다. 기존 토스 고객을 위해 토스 키와 운영 데이터를 유지한다. 변수를 설정하거나 운영에 배포하지 않았다.
- 공급사 공개 명세에서 독립적인 거래 조회를 확인하지 못했다. 통지 누락 및 최초 응답 유실 건은 관리자 대조 대상으로 드러나며 화면이나 수동 입력만으로 승인하지 않는다. 가맹점 관리자 거래 조회, 공급사의 통지 재전송 절차, 실제 승인 일시 형식·취소 필드·카드 유형·재전송과 KST, 통지 네트워크 인증, 관리자별 운영 권한, 정산 대조를 확인할 때까지 판매 보류다.
- 메일은 API 접수까지만 자동 추적한다. 실제 받은편지함 도착·반송 로그, 발신 도메인, 동일 주소로 재교부, 인증 환경에서 교부 시점을 확인한다. 카카오톡·인스타그램 실기기, 외부 결제창과 복귀, 실제 환불과 잔여 열람 처리는 미검증이다.
- 회귀 93개와 서버 통합 1개를 검증했다. 통합은 위조·금액 불일치·중복·응답 유실·메일 실패·다른 구매 접근·새 브라우저 이메일 복구·부분 취소 후 열람 보류를 실제 함수로 검사하고 공급사와 메일에는 합성 응답을 주입했다.
