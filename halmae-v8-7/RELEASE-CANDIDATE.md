## 상품과 테스트 결제

무료 체험은 브라우저에서 네 기둥과 일간·오행 등 핵심 결과를 표시한다. 상품 안내는 39,900원 예정가, 26장 구성, 가상 예시, 웹 열람 조건을 보여준다. 프리뷰의 카드 승인 후 발급한 웹 링크는 승인 시각부터 365일간 새 링크로 열람할 수 있다. 가입은 필요 없으며 선택 이메일 복구를 제공한다. 관리자 발급 토큰과 테스트 결제 토큰은 별도 범위를 사용한다.

서버는 주문을 발급한 브라우저의 서명 토큰, 주문 번호, 원화 39,900원, 토스 결제 키, 카드 상태 및 잔액을 확인한다. 토스 승인 요청에는 주문과 결제 키에서 생성한 멱등 키를 쓰고, 재시도 전에 이미 승인된 주문을 조회한다. 보고서를 열 때도 토스에 현재 결제 상태를 조회한다. 링크 유효기간과 데이터 보관 기간은 별개다. 발급 시스템은 공용 저장소로 간섭하지 않도록 이 프로젝트의 Netlify Blobs를 사용한다. 사이트 안의 테스트 결제 이벤트는 브라우저 탭에서 횟수만 기록한다.

빌드 출력에는 허용 목록의 정적 파일만 포함한다. 보고서 원고와 서버 함수는 배포 웹 루트에서 다운로드할 수 없다. 공개 GitHub 저장소에 올라간 공통 템플릿 자체는 공개 범위에 속하며, 개별 주문과 생성 보고서는 서버에서 권한을 검사한다.

- 출시 전 토스 테스트 키로 실제 프리뷰 승인·취소·중복 재시도와 복구를 확인한다. 실제 결제 환불 처리, 리다이렉트 이탈 시 주문 복구·정산 대조, 보관·자동 파기·삭제 절차, 최종 약관·청약철회 고지, 독립 만세력 경계 검증은 남아 있다.

## Issue #1 후속 검증

이 문서의 앞부분은 기준 커밋 `bdf2ddc`까지의 이력이다. 후속 버전은 26장을 유지하고, 계산·출생 기록 4장, 계산을 연결한 성찰 8장, 공통 14장으로 표시한다. 계절 비유는 기질과 일의 장에 남아 있으며 별도로 식별할 수 있다. 2027년 12장은 공통 계획 가이드다.

십성은 일간과 연간·월간·시간의 오행 순환 차이와 음양 일치 여부로 분류한다. 각 장의 질문은 일간 분류, 월간 및 연간의 십성 주제, 오행 최소 빈도와 동률, 시간 유무에 따라 달라진다. 질문과 일상 실험 예시는 전통 상징을 바탕으로 작성한 편집 규칙이며 성격·수입·관계 또는 사건 예측 점수로 사용하지 않는다. 건강과 재물은 실제 기록으로 판단하도록 안내한다. 구매 전 예시는 같은 입력과 규칙으로 검증한다.

- 1900년 1월부터 2026년 11월까지 월초 1,523개의 일주를 `korean-lunar-calendar@0.4.0`의 일진과 별도 대조했다. 불일치 0개다. 외부 라이브러리의 연·월 간지는 음력 표기이므로 이 서비스의 절기 연·월주 비교 기준에서 제외했다. [참조 구현](https://www.npmjs.com/package/korean-lunar-calendar/v/0.4.0)
- 2024년 대한·우수·춘분·하지·추분·동지의 분 단위 시각 6개는 홍콩천문대 공개 표와 일치했다. 2024년 입춘은 내장 표의 17:27 KST를 기준으로 전후 1분의 연주·월주 전환을 회귀 테스트했다. [홍콩천문대 2024년 절기표](https://www.hko.gov.hk/en/gts/astron2024/files/2024SolarTerms24.pdf)
- 23시 경계와 자정 처리, 출생 시각 미상 시 시주 누락 및 정오 기준을 확인했다. 연주·월주·시주 전 범위의 독립 명식 대조, 역사적 표준시와 출생지 태양시, 다른 자시 관례는 미검증이다. 용신·대운·세운·개인별 월운은 제공하지 않는다.

### 복구와 보존

프리뷰에 토스 테스트 설정과 `RECOVERY_RESEND_API_KEY`, `RECOVERY_FROM_EMAIL`이 모두 있어야 선택 복구가 열린다. 발신 이메일은 Resend에 검증된 도메인의 주소를 사용한다. 링크 추적 기능은 프리뷰 복구 메일에 적용하지 않는다. 복구에 별도 동의한 구매자의 주소는 서버에서 대조용 HMAC 값으로 저장하며, 브라우저 저장이나 전환 카운터에 포함하지 않는다. 주문 번호와 요청한 주소가 일치하면 입력한 주소로만 새 링크를 보낸다. 입력 일치 여부는 브라우저 응답에 공개하지 않는다.

복구 메일 링크는 최대 15분 동안 한 번만 교환할 수 있다. 승인 시각부터 365×24시간인 구매 만료를 주문에 저장하며, 웹 열람 링크는 최대 30분으로 각각 제한한다. 같은 브라우저의 보안 쿠키로 새 링크를 받을 수 있다. 이메일에 동의하지 않고 브라우저 데이터를 삭제하거나 기기를 바꾸면 복구할 수 없다. 동의한 구매자는 이메일과 주문 번호로 복구한다. 저장소의 조건부 생성으로 주문별 15분 시간대에 메일 발송 요청을 한 번만 처리하고, 링크의 중복 교환을 차단한다. 취소·부분 취소나 금액 변경은 매 열람에서 차단한다.

기존 승인 레코드는 토스 검증 후 신뢰된 승인 시각으로 365일 만료를 채우고 기존 이메일 원문을 대조용 검증값으로 변환한다. 기존 7일짜리 보고서 링크는 폐기되므로 등록 이메일로 새 링크를 받아야 한다. 이메일도 브라우저 등록도 없는 이전 테스트 주문은 새 브라우저에 소급 연결하지 않는다.

### 보존과 삭제

보고서 재생성에 필요한 생년월일과 선택 시각·별칭, 승인 검증 정보, 선택 이메일 대조값은 구매 열람 만료까지만 보존한다. 카드번호와 복구 이메일 원문은 새 주문 레코드에 보관하지 않는다. 법정 보존 의무가 생기는 실제 판매 기록은 필요한 거래·분쟁 정보만 별도로 보존하는 운영 절차가 필요하다. 삭제 요청은 구매자 확인 후 처리하며, 보고서 생성 정보 삭제 시 남은 열람분을 제공할 수 없다. 복구 동의만 철회하면 대조값을 제거하고 브라우저 열람은 유지할 수 있다.

정리 함수는 미승인·관리자 주문 30일 경과분, 승인 주문 열람 만료분, 만료한 복구 발송·사용 표식을 대상으로 한다. 미승인으로 남은 주문은 토스에 실제 승인이 있으면 보존한다. 이 작업은 기존 프리뷰의 `test-v87`에서 `PREVIEW_RETENTION_ENABLED=true`와 정상 토스 테스트 설정이 있을 때만 동작한다. 예약 실행과 실패 모니터링, 삭제 요청 처리 및 법정 보존 분리 저장소는 운영에서 검증해야 한다. 서명 키 교체 전에는 이전 HMAC 검증값의 이전 또는 재등록 계획이 필요하다.

### 전환과 출시 차단 요소

현재 카운터는 브라우저 탭을 벗어나면 집계할 수 없다. 집계 도입 시 별도 고지와 해당되는 동의를 적용하고, 동의 전에는 기존 탭 카운터만 사용한다. 집계는 단계별 이벤트 코드, 날짜 단위의 버킷, 실험군만 받는 검증된 엔드포인트로 설계한다. 생년월일, 메일, 주문번호, 보고서 링크, 결제 식별자, 원본 URL을 집계에 보내지 않는다. 개인별 추적 대신 일별 단계 합계와 전환율만 남긴다. 집계 전송은 이 변경에 포함하지 않았다.

실제 프리뷰에서는 토스 테스트 카드 승인·취소·중복 요청, Resend 발송·수신과 다른 기기 복구, 환불 정책, 개인정보 삭제 운영을 점검해야 한다. 본 변경은 기존 Netlify 프리뷰를 대상으로 하며 배포 상태는 실제 커밋 기준으로 확인한다.


## Issue #3·#4 무료 풀이에서 주문까지

무료 브라우저와 보고서 서버가 같은 양력·한국 시간 계산 코드를 사용한다. 무료 결과에서 일주의 일간으로 도입과 기질 질문, 일지로 관계 질문, 겉에 보이는 오행 분포로 일의 실천 제안을 고른다. 사주 기둥 및 오행 분포는 무료 결과의 상세보기에서 확인할 수 있다. 한국 시간 출생, 양력 전용, 시간 미상 시 시주 제외, 절기·밤 11시 무렵의 차이와 출생지 보정 미적용을 안내한다. 이 변경은 2027년 개인별 월운이나 만세력 전체의 독립 검증을 추가하지 않는다.

무료 결과에서 주문 버튼을 눌렀을 때만 검증된 별칭, 양력 날짜, 분 단위 출생 시각을 현재 탭의 세션 저장소로 넘긴다. 관계 상태는 무료 질문에서만 사용하며 저장·전송하지 않는다. 주문에서 입력을 수정하거나 지울 수 있다. 주문을 만들거나 입력을 지우면 이어가기 정보가 제거된다. 주문으로 보내기 전에는 출생 정보를 URL, 전환 카운터, 서버에 넘기지 않는다.

상품은 39,900원 26장 웹 보고서다. 나의 사주 기록 4장, 사주 요소를 연결한 성찰 8장, 2027년의 월별 글을 포함한 공통 가이드 14장으로 표시한다. 1월 목표 설정부터 12월 한 해 회고까지 각 달에 서로 다른 행동 계획과 점검 질문을 둔다. 테스트 결제 이용 여부와 이메일 복구 표시 여부는 프리뷰 서버 응답을 따르며, 기존 365일 열람 권한 및 링크 만료·환불 조건을 유지한다.

실제 프리뷰 배포와 토스·메일·예약 삭제 실연동은 인증된 프리뷰에서 확인해야 한다. 실제 판매 전에 거래기록 분리 보존·삭제 요청 처리, 최종 청약철회 및 환불 고지를 완료해야 한다.
